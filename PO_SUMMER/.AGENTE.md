# Mejores Prácticas de Automatización

Este documento establece las directrices para el desarrollo y mantenimiento de scripts de automatización, asegurando la calidad, la robustez y la facilidad de mantenimiento.

## 1. Principio de Cero Retrocesos
**Objetivo:** Garantizar que ningún cambio o nueva implementación en los scripts de automatización afecte negativamente la funcionalidad existente y ya verificada.

*   **No tocar lo que ya funciona:** Una vez que un script o una función ha sido validada y está funcionando correctamente, **no se deben realizar modificaciones sobre ella** a menos que una nueva característica la requiera explícitamente o se identifique un bug crítico que deba ser corregido.
*   **Prioridad a la estabilidad:** Cualquier nueva adición o refactorización debe diseñarse para coexistir con el código existente sin introducir efectos secundarios.
*   **Pruebas exhaustivas:** Antes de desplegar cualquier cambio, se deben ejecutar todas las pruebas relevantes para asegurar que no se han introducido retrocesos.

## 2. Prohibido Tocar Funciones Funcionales (Existentes y Validadas)
**Objetivo:** Proteger la integridad de las funciones que ya están en producción y han demostrado ser estables y confiables.

*   **Inmutabilidad de lo validado:** Las funciones o bloques de código que forman parte de la lógica central y han sido validados como funcionales y estables **no deben ser alterados**.
*   **Extensión sobre Modificación:** En lugar de modificar una función existente, se debe priorizar la creación de nuevas funciones o la extensión de la funcionalidad a través de métodos que no alteren el comportamiento original.
*   **Clara demarcación:** Mantener una clara separación entre el código de automatización y el código de la aplicación bajo prueba.

## 3. Implementación del Patrón Page Object Model (POM)
**Objetivo:** Mejorar la mantenibilidad, reducir la duplicación de código y facilitar la legibilidad de los scripts de automatización.

*   **Estructura del Proyecto:**
    *   Cada página o componente significativo de la interfaz de usuario debe tener su propia clase "Page Object" dedicada.
    *   Estas clases deben encapsular los elementos (localizadores) y las interacciones (métodos) de esa página/componente.
*   **Responsabilidad Única:**
    *   Una clase Page Object solo debe conocer los elementos y las operaciones que se pueden realizar en su página/componente correspondiente.
    *   No debe contener lógica de negocio ni aserciones.
*   **Abstracción de Localizadores:**
    *   Los localizadores de elementos (ej. `By.ID`, `By.XPATH`) deben ser privados o protegidos dentro de la clase Page Object.
    *   Los métodos públicos de la clase Page Object deben interactuar con estos elementos, abstrayendo los detalles de implementación de la interfaz de usuario.
*   **Reusabilidad:**
    *   Los métodos de los Page Objects deben devolver otras instancias de Page Object cuando la interacción resulta en una navegación a una nueva página.
    *   Esto permite encadenar las llamadas y simular el flujo de usuario de manera natural.
*   **Nomenclatura Descriptiva:**
    *   Las clases Page Object, los métodos y los localizadores deben tener nombres claros y descriptivos que reflejen su propósito (ej. `LoginPage`, `enterUsername`, `usernameInput`).

## 4. Estilo y Convenciones de Código
*   **PEP 8 (Python):** Adherirse a las guías de estilo de Python.
*   **Comentarios:** Utilizar comentarios solo para explicar el *por qué* de una decisión compleja, no el *qué* (el código debe ser auto-documentado).
*   **Nombres de Variables:** Claros, concisos y que revelen su intención.
*   **Funciones en español:** Preferir nombres de funciones y métodos en español, manteniendo la legibilidad y consistencia del código.
*   **Código entendible:** Escribir la mayor parte del código de forma clara y fácil de leer, evitando abreviaturas crípticas y constructos innecesariamente complejos.

## 5. Gestión de Dependencias
*   Si se requieren librerías externas no estándar, se debe indicar claramente y justificar su uso.

Al seguir estas prácticas, aseguraremos un entorno de automatización robusto, escalable y fácil de mantener.
